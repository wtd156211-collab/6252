# 幂等式格式化器（从 0 实现）

仓库里只有这份说明、`samples/**` 和 `.gitignore`，没有任何实现代码。

## 1. 范围

交付一个放在仓库根目录的 `tidyform` 包（Python 3.13，只用标准库）：

- 引擎：`tidyform.format_text(text) -> str`、`tidyform.count_changed_lines(before, after) -> int`、`tidyform.write_report(path, files) -> None`（`files` 是 `(显示名, 原文, 结果)` 的列表）。
- 命令行：`python -m tidyform 输入文件`（单个输入，结果写到 stdout）、`--write`（就地改写）、`--report 报告.html`（写报告，可与 `--write` 并用）。
- 交付时仓库里有一份自包含的报告 `diff-report.html`；测试用 `unittest`。

不做：重排语句、挪动注释、改字符串与参数；语义与类型检查；语句内部夹空行或独立注释行的输入；制表位展开与全角宽度换算（按 Unicode 码位计）；保留 CRLF（输出一律 LF）；目录递归；第三方依赖、构建步骤、联网，报告不依赖 JavaScript 或外部资源。

## 2. 口径与公式

### 2.1 空白

- **缩进**：一层 4 个空格；语句起始行缩进 0，续行按它所在的括号层级缩进，独立注释行缩进归零。输入原有的缩进（含制表符）一律重算。
- **行尾空白**：每行末尾的空格与制表符全部删除，注释行也一样。
- **行内间距**：两个词之间、`=` 两侧、`,` 之后各留一个空格；`(` 之前和之后、`)` 之前、`,` 之前不留空格。

token 分两类：字符串 `"…"`（`\"` 转义，里面的 `#`、括号、逗号都不是结构字符），以及被 `"`、`(`、`)`、`,`、`=` 切出来的词；空白只作分隔符。

### 2.2 空行与结尾

空行是块之间的一个间隔：连续多行折成 1 行，不跨独立注释行合并，也不会凭空多出；文件首尾的空行全删，输出以恰好一个 `\n` 收尾（缺了要补）；全是空白的输入输出 0 字节。

### 2.3 换行口径

每条语句先算**单行形状**：缩进 + 规范间距的 token 串 +（有行尾注释时再加两个空格与注释文本），宽度按 Unicode 码位计，≤ 100 列就单行输出。

超宽时只看语句里最左边的那个括号组：组内按顶层逗号切出的参数 ≥ 2 个就可拆；只有 1 个参数、而该参数自己是个括号组，就继续往里找。这样都找不到可拆的组，就保持单行，哪怕超宽。

拆一个组：首行保留左括号及它前面的 token；每个顶层参数各占一行，缩进比该组多一层，行尾补 `,`；右括号及其后的 token 单独成行，缩进与该组相同。参数行自身仍超 100 列时，对它内部的组重复同样的处理。语句的行尾注释固定挂在最后一行的末尾。

参数列表末尾的那个空参数（拆行留下的尾随逗号）不算参数：单行形状里不写它，拆行时逗号挂在每个参数行的末尾。

例：`f(a = 1, b = 2)` 超宽后是 `f(` / `    a = 1,` / `    b = 2,` / `)`；参数自己再拆时该行变成 `    fetch(`，收尾是 `    ),`。

### 2.4 幂等与最小改动

- 规范形状由上面的规则唯一确定：同一份输入永远得到同一份输出；对输出再跑一遍必须逐字节不变。
- 最小改动 = 只改写不合规范形状的语句、空行与行尾空白；语句顺序、注释归属、字符串内容、参数成员都不动。
- **改动行数** = 原文与结果的行级最长公共序列之外的行数（原文被替换或删除的行 + 结果新增的行，等于 diff 里红绿行之和）。报告顶部按这个口径算一次；`samples/expected-changes.txt` 逐文件给出上界，超出即不通过。

## 3. 状态机

按行读入，先把每行拆成「代码 + 注释」（注释从字符串外的第一个 `#` 起，`#` 之后原样保留，只删行尾空白），再归类：

| 行 | 识别 | 处理 |
| --- | --- | --- |
| 空行 | 去掉空白后没有内容 | 折进上一个空行；在首尾丢弃 |
| 独立注释行 | 去掉前导空白后以 `#` 开头 | 缩进归零，位置不动 |
| 语句（含续行） | 其余的行；括号计数没回到 0 就继续读下一行 | 攒成完整语句后整体重排 |

数据单位是一条单位序列：语句（token 列表 + 至多一个行尾注释）、独立注释行、空行。行尾注释属于语句而不是某一行，拆行后跟着语句走。

## 4. 输入输出与文件格式

### 4.1 输入约定

UTF-8 文本，`\r\n` 与 `\r` 先当 `\n`；一条语句的括号必须配平，一行只属于一条语句；空行与独立注释行不出现在语句内部；一条语句最多一个行尾注释；字符串不跨行。格式化器要能读回自己写出的文件：再跑一遍必须逐字节不变。不符合约定按 4.2 报错。

### 4.2 命令行

```
python -m tidyform 输入文件                 # 只允许一个输入，结果整个写到 stdout
python -m tidyform --write 输入文件...
python -m tidyform --report 报告.html 输入文件...
```

`--report` 只额外产出报告，改不改写仍由 `--write` 决定。输入读不到或不符合 4.1 时不写文件，stderr 给出原因，退出码非 0；成功退 0。

### 4.3 报告

- 单个 HTML 文件，双击就能打开；不引外部资源、不发网络请求、不依赖 JavaScript。
- 顶部：每份文件的改动行数与幂等自检结果（对自己的输出再跑一遍，必须零改动）。
- 主体：每份文件左右逐行对照，左栏原文、右栏结果，两侧都给行号，改动过的行有可见标记。
- 行号与改动标记取自引擎这一次的格式化结果，报告层只排版。

## 5. 性能与验收口径

预算（冷启动，含读写与报告）：单文件 ≤ 8 MB、≤ 10 万行；`samples/input/large.task`（约 3.1 万行）≤ 3 秒，`samples/input/` 全部 ≤ 10 秒；给它生成报告 ≤ 15 秒、HTML ≤ 8 MB。只用标准库，不加依赖与构建步骤。

1. `samples/input/` 每个文件跑一次，结果与 `samples/expected/` 同名文件逐字节相同（空文件也是 0 字节）。
2. 对每份结果再跑一次，逐字节不变，报告里的幂等自检为通过。
3. 改动行数不超过 `samples/expected-changes.txt` 的上界（表里留了少量余量）。
4. 行尾注释跟着所属语句，独立注释行不被上下语句带走。
5. 连续空行折成 1 行，首尾不留空行，文件以恰好一个 `\n` 收尾。
6. 规模与耗时不超过本节开头的预算；报告能双击打开、无网络请求，含 4.3 的必现信息；测试用 `unittest`。

## 6. 样例说明

`samples/input/` 与 `samples/expected/` 同名一一对应；上界列来自 `samples/expected-changes.txt`。

| 文件 | 覆盖的场景 | 上界 |

| `comments.task` | 行尾注释拆行后跟到 `)` 行、独立注释行带缩进、注释不许漂到邻句 | 21 |
| `blank-lines.task` | 连续空行与只含空白的行、首尾空行、行尾空白 | 12 |
| `long-args.task` | 顶层拆行、参数内部再拆一层、只有 1 个参数的语句超宽也不拆 | 39 |
| `messy.task` | 行内多余空格、被拆开的语句合并回一行、制表符缩进、注释前空格 | 11 |

| `empty.task` | 0 字节输入输出 0 字节 | 0 |
| `large.task` | 约 3.1 万行的混合文件：性能、幂等与改动上界一起对 | 8682 |
